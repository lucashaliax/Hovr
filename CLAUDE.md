# Hovr

A menu bar Mac app for visual references. A global shortcut (⌥⇥ by default) freezes the screen and shows a selection: drag an area (⇧ square, ⌥ + clicks free-form, Space a whole window). In **Image** mode the image is copied and pinned as a floating card (the selection's shape and size, where it was selected) above every window (all Spaces, over full-screen apps). In **Text** mode the text in the area is read (Vision OCR) and copied; a plain click makes an empty **note** card there (rich text, checklists, lists). Cards can be thrown/dragged to a screen edge to dock as thumbnails. Every capture and note goes to Recents (a gradient panel from the right edge, ⌃⌥H), kept for 7 days (3/7/14/30 days or never).

It is an original app inspired by what the user relied on in Obry (a paid, closed-source app). Do not copy Obry's code, assets, name or look. Name chosen by the user: **Hovr** (bundle id `app.hovr.Hovr`). It was developed as the draft "Clone" (`app.clone.Clone`); `App/Migration.swift` moves that draft's settings, captures (`~/Pictures/Clone` → `~/Pictures/Hovr`), list and logs on first launch. Permissions (Screen Recording, Input Monitoring) are per bundle id, so they had to be granted again.

## Layout

- `App/AppDelegate.swift`: entry point, language, status item, global hotkeys (capture, Recents, hide/show cards), Settings window. `-HovrPreview menu|settings|advanced|shortcuts|sound|capture|recents|pin|cardmenu|dock|note` opens one piece of UI to check its look (`note` creates a real sample note; `dock` docks the latest card).
- `App/MenuPanel.swift`: the menu bar popover (244 pt wide, 13 pt text, native menu proportions) (glass on macOS 26+, popover material before): two big capture buttons, Recents, Close All Cards, Settings, Quit. Opens with a spring from the icon, closes on outside click or Esc.
- `App/CaptureController.swift`: Screen Recording permission, freezes each screen with ScreenCaptureKit (`SCScreenshotManager`), lists windows for click-to-capture, finishes a capture (shutter sound; copy + pin flying out of the selection, or OCR + copy; free-form shapes are masked to transparency), creates notes, records the source app.
- `App/SelectionOverlay.swift`: the full-screen selection window. Layer-based: the frozen screen is the root layer's contents and is never redrawn. The highlighted rectangle (selection or hovered window) glides to its target on a display link that stops when it arrives, clear inside (no tint, by request), a thin bright line and a discreet glow outside the edge (three shadow layers, masked outside, breathing via Core Animation). Colour per mode: blue = Image, red = Text (`CaptureMode.color`). Clicking a window to capture it is optional and off by default ("Window click" toggle in the menu bar popover, `clickToCaptureWindow`; Space switches it for one selection); ⇧ makes a square; holding ⌥ and clicking corners makes a free-form shape (captured when ⌥ is released); a plain click makes a note in Text mode and does nothing in Image mode. A badge next to the crosshair shows the mode (plus a hint for the first 5 captures). Keys: Tab/I/T/Esc/Return.
- `App/Cards.swift`: `CardManager` (open cards, standard sizes, hide/show all, restore after relaunch incl. docked state) and `CardWindow` + `CardHostView` (shared by image and note cards): drag to move, edge resize (images keep their shape), pinch (accumulated from the gesture start). Pinches don't reach a background app reliably, so `CardManager` runs a listen-only `CGEvent` tap for gesture/magnify events when Input Monitoring is granted (Settings → Advanced), with `.magnify` event monitors as a fallback; every pinch and the permission state at launch go to `~/Library/Logs/Hovr/diagnostics.log` (`Diag.log`; NSLog lines don't show up in `log show` for this app). `-HovrPreview askinput` asks for Input Monitoring, ⌘-scroll/mouse-wheel zoom, ⌥-scroll opacity, two-finger move with the pointer warped along (`CGWarpMouseCursorPosition`, so the card never slips from under it), throws with our own inertia (system momentum ignored), docking at a screen edge like Obry's video (the card keeps its size and slides off the edge until only a 12 pt tab shows, at the height it hit; hovering pulls it out 10 pt; click slides it back where it was; dragged away it stays where dropped; no docking at an edge shared with another screen. A perspective/thumbnail look was tried and rejected by the user), lock (⌘L), ⌘0–9 opacity, ⌘W. Image cards: the card's shape is the image's (`fixedAspect` comes from the image, never from the window frame, whose pixel rounding made the shape drift during pinches); the whole image is always shown (aspect fit); hover buttons ✕ (red Mac traffic-light, also on notes) / extract text / ⋯.
- `App/Notes.swift`: note cards. TextKit 1 `NoteTextView` (checkbox attachments clickable; `[ ] `, `- `, `* `, `1. ` shortcuts; Return continues lists; ⌘B/I/U, ⇧⌘X, ⌘±, ⇧⌘V, Esc). Saved as `Hovr Note <date>.rtfd` in the captures folder (checkbox state is in the attachment file name), as History entries with `isNote`.
- `App/CardMenu.swift`: the ⋯ menu (copy, note colours + custom colour, opacity slider, lock, close/delete) in a `GlassPanel`.
- `App/RecentsPanel.swift`: Recents panel (430 pt wide, full screen height under the menu bar and behind the Dock; a behind-window blur masked by a smoothstep fade plus a long eased black gradient, so it fades in with no visible edge; macOS 26 scroll-edge blur turned off; square 1:1 tiles with a small steady tilt; grouped by day; click to pin/open, right-click menu).
- `App/History.swift`: captures as `Hovr <date> at <time>.png` (plus `.txt` for Text captures) in a folder the user picks, `~/Pictures/Hovr` by default (`storageFolder`); the list is `~/Library/Application Support/Hovr/index.json`. Changing the folder moves the files. Captures deleted in Finder drop out of Recents. Pruning, cached thumbnails, OCR on demand.
- `App/AppSettings.swift`, `App/Settings/`: settings and the Settings window (translucent, sidebar with icon; panes General, Cards (note colour, throw intensity, displays, interaction, gestures), Sound & haptics, Shortcuts (3 recordable global shortcuts + reference of in-app keys), Advanced, About; Advanced has permissions, captures folder, keep 3D/7D/14D/30D/Never, Open Recents, Clear storage, Reset all settings). Sized like a native settings window (620×460, 12.5 pt rows).
- `App/Utilities.swift`: OCR, clipboard, HUD, `PopAnimation` (menus grow out of their button with a spring and fade; used by the menu bar popover and the ⋯ menu, on a wrapper view, never the content view). Sounds/haptics: `Feedback` in `AppSettings.swift` (system sounds Screen Capture.aif and SentMessage.caf, `NSHapticFeedbackManager`).
- `App/Updater.swift`, `HotkeyCenter.swift`, `Shortcut.swift`, `KeyNames.swift`, `Settings/ShortcutRecorder.swift`: from Floatr.

## Build

- `tools/build.sh --draft`: builds Release into `~/Library/Developer/Xcode/DerivedData/Hovr-cli`, runs it from there (no install), then `tools/check_resources.sh`. `tools/build.sh` (no flag) installs to /Applications; `--zip` writes `build/release/Hovr.zip`.
- `Hovr.xcodeproj` is generated by `tools/gen_project.py` (team WLWCRYCLRT kept). Rerun after adding files.
- Translations: `python3 tools/make_strings.py`. Icon: `cat App/HovrGlyph.swift tools/make_icons.swift > /tmp/hovr_icons.swift && swift /tmp/hovr_icons.swift` (app icon). The menu bar icon is drawn at runtime by `HovrGlyph` (template, 18 pt): a rounded square whose top-right corner peels back in a round fold.
- Keep only the Release build in DerivedData: macOS once relaunched an old Debug copy after a permission prompt ("quit and reopen"). The Debug copy was removed.
- Debug build only: `open Hovr.app --args -HovrDemo YES` pins a generated card and reads its text (no Screen Recording needed).
- Two-finger move/throw, pinch and real captures need a person at the trackpad: they can't be checked from the command line.

## Decisions

- Carbon hotkey (no Accessibility permission). Pressing the shortcut again during a selection switches Image/Text.
- The screen is captured before the overlay appears, so the selection shows a frozen image (menus and hovers stay as they were).
- Cards are non-activating panels at `.floating` level: clicking one doesn't take focus from the app you work in, but it still gets keys (⌘C, typing in notes…). There is no main menu, so notes handle ⌘C/⌘V/⌘X/⌘A/⌘Z themselves.
- Cards take the selection's shape and size and appear right where it was selected (like Obry). A standard square shape was tried and dropped by the user. Pinned from Recents: natural size, at most 60% of the screen, centred. Double-click: back to natural size. Image cards darken their top behind the buttons (`TopShadeView`).
- Click-through cards were removed (replaced by lock, Obry-like).
- Interface language is set through `AppleLanguages` at launch without restarting the process (a restart with `execv` broke the menu bar item on first launch).
- The selection screen follows the user's request for a clean, pointer-following look like the one they used in Obry, drawn in Hovr's own style (system accent colour, SF Symbols), not copied.
- Obry uses the same ⌥⇥ shortcut: while Obry runs, Hovr shows "Another app already uses this shortcut".

## Status (2026-11-24)

- Renamed to Hovr with its own icon (`App/HovrGlyph.swift`, concepts in `docs/naming/`). Card entrances (lift after a capture, new note, reopen) run on Core Animation: the window is placed at its final frame and only the host's layer is scaled/faded (`CardHostView.animateEntrance`; the host sits in a plain container view because AppKit manages the content view's layer). Moves that need checks along the way (dock, undock, peek, inertia, keep on screen) use our display-link spring (`CardWindow.glide`, measured at 0.2–0.4 ms per frame); new notes fade in softly; notes leave editing after 20 s idle or when another Hovr window takes the keyboard. Idle CPU 0.0% (the resource check waits 12 s, restoring cards takes a moment).
